# Чем генерят конкуренты и что брать нам

Проверено веб-поиском 2026-08-02. Оценки моделей — из сторонних бенчмарков,
не наши замеры.

## Три подхода к консистентности персонажа

Рынок в 2026 сошёлся на трёх способах «запирать» персонажа:

| Подход | Как работает | Модели | Правило 9 |
|---|---|---|---|
| **Edit-based** | правка исходного изображения инструкцией, персонаж переносится между сценами | FLUX Kontext | **разрешено** |
| **Reference-based** | референс подаётся вместе с промптом | Nano Banana 2/Pro, GPT-Image 2, Midjourney omni-ref | **разрешено** |
| LoRA-based | дообучение весов на фотографиях | Stable Diffusion / Pony экосистема | **запрещено** |

## Главная новость: строгое толкование правила 9 почти ничего не стоит

Заявленные показатели FLUX Kontext: **97% сохранения лица и 92% сохранения костюма
на 20 последовательных генерациях**. Это edit-based подход — **без обучения весов**.

Наш порог — 90% разворотов ([track-b-runbook.md](../track-b-runbook.md)).
Технология без обучения его перекрывает с запасом.

> **Вопрос Q1 (можно ли одноразовые адаптеры) с высокой вероятностью потерял
> практический смысл.** Мы вводили строгое толкование, ожидая, что оно стоит нам
> качества. Похоже, не стоит. Окончательный ответ — из книг №1–3, но ставить
> на пересмотр правила 9 больше не нужно.

Косвенное подтверждение выбора метрики: по опросу февраля 2026 **73% родителей
назвали консистентность персонажа главной претензией к AI-книгам**. Мы меряем
ровно то, что рынку болит.

## Конфликт: лучшая модель — худшие условия по данным

| Вендор | Обучение на вводе API | Пригодность по правилу 9 |
|---|---|---|
| OpenAI API | не обучают с 2023 по умолчанию; бизнес-тарифы — явно нет | **пригоден** |
| Google Gemini (business/enterprise) | по умолчанию не обучают | **пригоден** |
| **Black Forest Labs (FLUX API)** | условия использования данных **шире**, чем у Google и OpenAI | **не пригоден как есть** |

Ирония: технически лучший инструмент для нашей задачи поставляется с самыми
широкими правами вендора на данные. Прямо использовать его API для детских
фотографий нельзя.

## Решение — своя генерация на открытых весах

**Рекомендация: edit-модель класса FLUX Kontext на открытых весах, развёрнутая
на арендованной GPU в российском ЦОД.**

Что это закрывает одним решением:

1. **Правило 9** — веса не дообучаются, фото не покидают наш периметр;
2. **вендорские условия** — их просто нет, мы не отправляем данные наружу;
3. **трансграничную передачу** — 152-ФЗ требует, чтобы обработка данных
   российских граждан велась с использованием баз на территории РФ; отправка
   фотографии ребёнка в зарубежный API — это отдельный юридический вопрос,
   которого лучше не иметь (проверить у юриста);
4. **пиннинг версии** — вендор не может молча обновить модель и сломать
   допечатку ([illustration-consistency.md](../illustration-consistency.md)).

Цена: аренда GPU и инженерное время на развёртывание. На объёме 20–25 книг
в месяц это дороже, чем API. **Мы платим не за качество, а за то, чтобы
не иметь юридического риска.** С учётом штрафов до 500 млн ₽
([market-research.md](../business/market-research.md)) это дешёвая страховка.

**Запасной вариант**, если своя генерация не взлетит: коммерческий API
с письменной гарантией «не обучаем на вводе» (Google или OpenAI в бизнес-тарифе)
плюс отдельное согласие клиента на трансграничную передачу. Это работает,
но добавляет юридическую конструкцию, которую придётся объяснять родителю.

## Псевдонимизация перед отправкой в LLM

Текст можно генерировать внешней моделью — он не биометрия. Но в промпте
всё равно оказываются имя ребёнка, город, детали быта.

**Приём: перед отправкой заменять персональные данные плейсхолдерами,
подставлять обратно локально.**

```
интейк:   «Мирон складывает машинки от двери до кухни»
в модель: «{HERO} складывает машинки от двери до кухни»
обратно:  «Мирон складывает машинки от двери до кухни»
```

Стоит полчаса работы, снимает целый класс вопросов и не влияет на качество
текста: модель одинаково хорошо пишет про `{HERO}`.

## Итоговый стек

| Слой | Выбор | Почему |
|---|---|---|
| Транскрипция интервью | локальная модель класса Whisper | голос клиента не уходит наружу |
| Извлечение структуры из транскрипта | LLM + псевдонимизация | заполняет Character и Relationship |
| Текст по разворотам | LLM + псевдонимизация, жёсткий JSON-контракт | развороты, а не «сказка целиком» |
| Гейты текста | детерминированные проверки + LLM-судья | часть ловится регулярками, часть — моделью |
| Лист персонажа | edit-модель на открытых весах, свой сервер | правило 9 + локализация |
| Развороты | та же модель, обусловленная листом | ошибка от одного канона |
| Авто-QA консистентности | сравнение **разворота с листом персонажа** | фото ребёнка в проверке не участвует |
| Вёрстка и превью | HTML + CSS, рендер в PDF | версионируется, диффится, автоматизируется |
| Хранилище | S3-совместимое в РФ, шифрование, TTL | политика удаления исполняется машиной |
| Оркестрация | своя очередь заданий | ПДн через сторонние low-code сервисы не гоняем |

**Важная деталь про авто-QA.** Автоматическая проверка консистентности сравнивает
сгенерированный разворот с **листом персонажа**, а не с фотографией ребёнка.
После утверждения листа фотография в пайплайне больше не участвует вообще —
и это же позволяет удалить оригиналы через сутки (D-012).

## Чего не делаем

- **Подстановки лица** в готовую иллюстрацию — чужой приём, даёт результат,
  который ребёнок читает как «это не я».
- **Low-code оркестраторов** (n8n и подобных) в контуре с детскими фотографиями —
  удобно, но добавляет ещё одного обработчика персональных данных.
- **Готовых платформ-генераторов книг** — они решают ту задачу, от которой мы
  отличаемся: собрать книгу быстро. Наша ценность в редактуре, а её они не дают.
