# Приватность и обращение с фотографиями

Privacy-by-design. Правила 8, 9, 10 Конституции реализуются механизмами, а не обещаниями
в оферте.

## Классы данных

| Класс | Примеры | Режим |
|---|---|---|
| `original_photo` | загруженные фото ребёнка или питомца | шифрование, TTL, журнал доступа |
| `derived_visual` | кропы, маски, референсы для генерации | живут не дольше оригинала |
| `descriptor` | `AppearanceDescriptor`, черты характера | текст, переживает удаление фото |
| `artifact` | макет книги, PDF в печать | хранится по обязательствам перед клиентом |
| `telemetry` | логи пайплайна | **никогда** не содержат изображений и лиц |

Ключевой приём: после утверждения `CharacterSheet` продукт зависит от `descriptor`
и канона, а не от `original_photo`
([illustration-consistency.md](illustration-consistency.md)). Поэтому удаление
оригиналов не ломает ни производство, ни допечатку — и происходит уже через сутки
после утверждения листа, а не после отгрузки. Окно риска сокращается с недель до часов.

## Жизненный цикл оригиналов

```
upload → encrypted vault (ключ на проект)
       → доступ только пайплайну генерации и назначенному редактору
       → после утверждения CharacterSheet: оригиналы больше не нужны (D-012)
       → hard delete по наступлению первого из событий:
           • лист персонажа утверждён + 24 часа
           • заказ archived (книга отгружена) + 14 дней
           • отмена заказа — немедленно
           • запрос клиента на удаление — не позднее 72 часов
           • TTL с момента загрузки — 90 дней, безусловно
       → в журнале остаётся факт удаления, без содержимого
```

Бессрочное хранение запрещено по умолчанию (правило 8). Продление возможно только по
явному запросу клиента, на срок, с датой окончания.

## Детские фотографии — максимальный режим (правило 10)

Дополнительно к общему режиму:

- **Согласие** оформляется до загрузки, не после: кто загружает, кем приходится ребёнку,
  на что именно согласие (иллюстрация, превью, печать), срок;
- **Минимизация доступа**: один назначенный редактор на проект, доступ снимается при
  переходе в `archived`;
- **Журнал** доступа: кто, когда, зачем открыл; журнал не удаляется вместе с фото;
- **Право на удаление** — самообслуживанием, а не через переписку;
- **Никаких публичных превью-ссылок**: превью открывается только заказчику;
- **Портфолио и маркетинг**: детские работы не публикуются без отдельного согласия,
  оформленного отдельно от согласия на изготовление.

Детский флагман не стартует, пока это не реализовано и не проверено (см.
[strategy.md](strategy.md), критерии перехода).

## Обучение моделей — правило 9

**Запрещено обучать любые модели на пользовательских фотографиях.**

Практическое следствие: техника достижения консистентности персонажа ограничена. До
решения владельца по Q1 из [constitution.md](constitution.md) система проектируется по
строгому толкованию:

| Разрешено | Запрещено |
|---|---|
| reference-conditioning без обучения весов | per-order LoRA / DreamBooth / textual inversion |
| текстовый `AppearanceDescriptor` как носитель внешности | накопление датасета пользовательских фото |
| ручная доработка художником | передача фото вендору с правом обучения |
| промпт-инжиниринг и seed-контроль | «анонимизированные» выборки для дообучения |

**Отдельно про вендоров.** Любой внешний API генерации проверяется на условие
«не использует ввод для обучения». Если вендор не даёт такой гарантии письменно —
он не используется для пользовательских фото. Это ограничение на выбор поставщика,
и оно может оказаться дороже; цена этого решения принята сознательно.

## Юридическая рамка РФ (152-ФЗ)

Проверено 2026-08-02, подробности и источники — [business/market-research.md](business/market-research.md).
Требует подтверждения юристом; ниже — рабочая рамка, а не заключение.

| Что | Следствие для нас |
|---|---|
| Ст. 11: биометрия обрабатывается **только с письменного согласия** | мы переносим черты лица ребёнка ради узнаваемости — риск попадания под ст. 11 реален |
| Согласие даёт законный представитель (ст. 64 СК РФ) | галочка на сайте недостаточна |
| Оператор уведомляет РКН **до начала обработки** | сделать до первой загрузки клиентского фото |
| Утечка: до 20 млн ₽; повторная — оборотный штраф до 500 млн ₽ | правило 10 стало финансовым риском, а не только этическим |
| Уведомление об утечке — **24 часа**, расследование — 72 часа | регламент должен существовать до первого заказа |
| Передача подрядчику **не снимает** ответственности | утечка у вендора генерации — наша ответственность |

Практический вывод: юридический пакет — не расход «на всякий случай», а условие
запуска. До его готовности детские фотографии клиентов не принимаются.

## Проверяемость

Приватность считается работающей, только если это видно из системы:

- гейт `privacy.assets` падает, если оригинал утёк в артефакт или лог;
- отчёт по удалениям: сколько оригиналов должно было быть удалено и сколько удалено;
- расхождение в отчёте — инцидент, а не «поправим потом».

На concierge-этапе отчёт может быть ручным чек-листом. Но он должен существовать
с первой книги, иначе привычка не сформируется.
